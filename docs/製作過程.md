# 風景印地圖・東京：製作過程

這份文件記錄這個網頁怎麼從想法變成可以用的工具，包括每個決定的原因、遇到的問題和解法。之後要更新資料，或擴大到其他都道府縣，可以照著這裡做。

## 1. 起點：要解決什麼問題

日本郵局的風景印不是每間都有。去之前不知道哪間有，常常白跑一趟。

目標：做一個**手機上用的地圖**，出發前和走在路上都能確認哪間郵局有風景印，並記錄自己收集了哪些。

## 2. 規劃時做的決定

| 項目 | 決定 | 原因 |
|---|---|---|
| 地區 | 先做東京都 | 下一趟旅行去東京；資料量小，容易檢查 |
| 裝置 | 手機優先，電腦也能用 | 主要在旅途中使用 |
| 使用者 | 只有自己 | 先求好用，之後再考慮分享 |
| 語言 | 介面用中文，郵局名、圖案說明保留日文 | 日文原名方便在現場對照招牌 |
| 地圖上顯示什麼 | 只顯示**有**風景印的郵局 | 官網只列出有風景印的郵局。地圖上沒有的就是沒有，畫面也比較乾淨 |
| 收集紀錄 | 每款風景印分開記錄，存在手機瀏覽器，可以匯出／匯入備份 | 有些郵局同時有新舊兩款圖案；先不架資料庫，比較簡單 |

### 地圖：為什麼選 MapLibre

比較過三種做法：

| | Leaflet + OpenStreetMap | **MapLibre + OpenFreeMap**（採用） | Mapbox |
|---|---|---|---|
| 費用 | 免費 | 免費 | 有免費額度，超過要付費 |
| 註冊／金鑰 | 不用 | 不用 | 要申請 token |
| 外觀 | 普通 | 漂亮，可以自訂 | 最精緻 |

MapLibre 是 Mapbox 地圖程式的開源分支，用法幾乎一樣，但不用註冊也不用付費。之後想換成 Mapbox，要改的地方很少。

### 定位

手機瀏覽器本來就能定位，跟用哪一套地圖無關。限制：

- 網頁必須是 https
- 第一次使用要按「允許」
- 東京高樓多，定位可能差到幾十公尺

## 3. 資料：從哪裡來、怎麼整理

### 3.1 資料來源

日本郵便官網的風景印資料庫：<https://www.post.japanpost.jp/enjoy/culture/stamp/fuke/>

- 清單頁：`result_pre.php?pref_id=13`（13 是東京都），之後用 `item.php?pref_id=13&page=N` 繼續往下載入
- 詳細頁：`detail.php?id=XXXX`，內容有使用開始日、圖案說明、圖案作者、地址、備考

清單頁還會標出「〇〇廃止予定」（即將廢止）和「〇〇使用開始」（新圖案），這兩個標記都有保留。

### 3.2 抓取步驟

| 步驟 | 程式 | 結果 |
|---|---|---|
| 抓清單 | `scripts/fetch_list.py` | 東京都 721 款風景印 |
| 抓詳細頁 | `scripts/fetch_detail.py` | 每頁間隔 1 秒，不給官網造成負擔，約 15 分鐘；可中斷後續跑 |
| 整理＋轉座標 | `scripts/build_data.py` | 依郵局合併，輸出 `data/tokyo.json` |

### 3.3 整理時遇到的問題

| 問題 | 解法 |
|---|---|
| 清單頁有重複資料（761 筆，不重複的只有 721 筆） | 用風景印 id 去重複 |
| 同一間郵局有多款圖案（新舊並存、換圖案中） | 以「郵局名＋地址」合併，一間郵局底下放多款 |
| 「備考」被混進圖案作者或圖案說明 | 用「備考」二字切開，另外存成備註，在網頁上收合顯示 |
| 74 款沒有圖案說明 | 確認過是官網本身沒寫（多半是較舊的資料，例如三宅島），網頁上顯示「官網未提供說明」 |
| 地址有錯字或寫法特殊 | 在 `build_data.py` 的 `ADDR_FIX` 中修正，例如「千代区」改成「千代田区」、「日原」補上「奥多摩町」 |
| 全形數字、長音符號「ー」被當成連字號 | 先做 NFKC 正規化，數字之間的「ー」換成「-」 |

### 3.4 地址轉座標

使用**國土地理院**的地址搜尋 API（`msearch.gsi.go.jp`）：免費、不用註冊，日本地址最準，大多可以對到門牌號碼。

- 702 間郵局全部轉換成功
- 其中 18 間只能對到「町」等級，大多在離島、山區，或位於活動會場內。這些會標為 `approx`，網頁上提醒「位置為大約位置，請以地址為準」
- 結果存在 `raw/geocode_cache.json`，下次更新只查新增的地址

### 3.5 最後的資料

- **702 間郵局、721 款風景印**
- 每間郵局：名稱、郵遞區號、地址、區市町村、座標，以及是否為大約位置
- 每款風景印：使用開始日、圖案說明、作者、備註、廢止日或開始日、官網連結

風景印圖案的著作權屬於日本郵便，所以網頁**不放圖片**，改成連結到官網的詳細頁。

## 4. 網頁功能

- 地圖標記：🔴 未收集、🟢 已收集、白底紅框：部分收集（多款圖案中收了一部分）、🟠 外圈表示 45 天內即將廢止，或剛開始使用的新圖案
- 篩選：未收集、已收集、全部、即將廢止／新圖案，也可以選區域
- 搜尋：郵局名、地址、圖案說明
- 附近清單：依你的位置排序，沒開定位時改用地圖中心
- 郵局詳細資料：導航（Google Maps 步行）、查營業時間、官網連結
- 收集紀錄：每款分開標記，可以修改日期；匯出／匯入 JSON 備份
- 收集日期使用手機的當地日期（一開始用世界標準時間，在日本早上 9 點前會記成前一天，已修正）
- 深色模式：跟著手機設定自動切換

## 5. 放在哪裡：為什麼用 GitHub Pages

一開始打算發布成 Claude 的私人網頁，後來發現它為了安全有兩個限制：

1. 不能使用定位
2. 不能載入外部的地圖圖資，地圖會一片空白

所以改用 **GitHub Pages**：免費、有 https、定位和地圖都能正常使用。限制是免費帳號的儲存庫要設成 Public（公開），但收集紀錄只存在手機上，不會上傳。

MapLibre 程式庫直接放在 `vendor/` 資料夾，不依賴外部 CDN。

## 6. 設定過程紀錄

### 6.1 Claude 雲端環境的「允許的網域」

雲端環境預設只能連到套件來源。這次加了三個網域：

| 網域 | 用途 |
|---|---|
| `www.post.japanpost.jp` | 抓風景印資料 |
| `msearch.gsi.go.jp` | 地址轉座標 |
| `tiles.openfreemap.org` | 測試時載入地圖圖資 |

### 6.2 連接 GitHub

1. 在 GitHub 建立儲存庫 `fukeiin-map`，設為 **Public**
2. 在 claude.ai 的 GitHub 設定頁（Built-in integration），先連接 GitHub 帳號
3. **另外安裝 Claude GitHub App**：帳號連接成功不代表已經安裝。設定頁顯示「Not installed」時，要按 **Fix** 安裝，選 **Only select repositories**，只勾 `fukeiin-map`
4. 另一個名為「github」的 Connector 是聊天時操作 GitHub 用的，這次用不到

### 6.3 開啟 GitHub Pages

Settings → Pages → Source 選 **Deploy from a branch** → Branch 選 **main**、資料夾選 **/ (root)** → Save

網址：<https://simpleouo.github.io/fukeiin-map/>

## 7. 已知限制

- 資料是某一天的快照，風景印會新增和廢止。網頁的「設定與備份」裡有寫資料日期
- 收集紀錄只存在單一瀏覽器，換裝置要靠匯出／匯入
- 不顯示郵局的營業時間，要透過「查營業時間」到 Google Maps 確認。風景印只能在窗口營業時間內押印，很多小郵局週末不營業

## 8. 之後可以做的事

- **更新資料**：照 README 的三行指令重跑
- **其他地區**：把程式裡的 `pref_id=13` 換成其他都道府縣的編號（官網下拉選單裡的值），並調整 `build_data.py` 裡寫死的「東京都」
- **雲端同步**：讓手機和電腦的收集紀錄自動同步，需要另外接資料庫服務（例如 Supabase、Firebase）
- **自動更新**：用 GitHub Actions 定期重跑抓取程式
